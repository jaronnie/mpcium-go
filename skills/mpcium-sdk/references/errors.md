# SDK v0.5.0 的错误边界

这些说明对应已验证的 v0.5.0，实现升级后应重新检查，不能把历史行为当成永远不变的接口保证。

| 现象 | 判断和处理 |
| --- | --- |
| 连接返回 `authorization violation` | 可能是来源 IP 不在任何已授权资源白名单中，也可能是 token 无效、凭据已轮换或没有有效资源。不能只凭此错误认定唯一原因。核对当前凭据与目标资源的实际 IP 规则。 |
| 已连接，但发布出现 `Permissions Violation` | 项目内其他资源允许连接，不代表本次目标资源也获准访问。核对目标 `walletID` / `keyDataId`；保持资源隔离，不通过扩大白名单或改用内部账号绕过。 |
| 权限被拒后，SDK 等待约 45–60 秒才返回 | NATS 的发布权限错误走异步错误回调；当前业务方法仍等待签名/加密业务回复，未将该异步错误关联到请求提前结束。数据和导出通常等约 45 秒，签名模板上下文约 60 秒。服务端已拒绝请求，等待不表示后台还在允许执行。不要把这个延迟归因于 MPC 计算、数据库查询或慢 IP 匹配。 |
| `context deadline exceeded` | 单看超时不能认定是权限拒绝。也可能是网络、节点或已开始的 MPC 操作未及时返回。不要自动重新提交签名/创建；先按请求 ID 检查状态并遵循用户的重试范围。 |
| TLS `EOF`、证书或域名错误 | 连接失败不是验签失败或 IP 拒绝的证据。保留 TLS 验证，检查服务地址和网络。确认失败发生在提交之前，才能按任务授权重新连接。 |
| SDK 返回签名/公钥不匹配 | 不向下游交付签名，不使用返回结果替换固定公钥。检查钱包 ID、曲线、公钥和原始签名输入。 |
| Solana 导出得到 32 字节，但公钥不符 | 32 字节长度不能证明曲线正确。使用 `ExportWallet(ctx, walletID, types.KeyTypeEd25519)`；配套入口与节点必须支持导出请求的 `key_type`。 |
| 加密项目凭据无法解锁 | 区分 Base64 格式错误与密码/age 解锁错误。不打印密文解密结果、token 或密码用于排查。重新导出凭据会轮换 token，不能把它当成无副作用的默认排查步骤。 |

检查 NATS 拒绝和 SDK 超时时，应分别报告“服务端是否已拒绝”和“调用方何时收到错误”。当前 skill 只指导正确接入，不假定这个异步错误传播限制已经修复。
